# Reproduction of the Manuscript Results

This document describes the procedure that reproduces the simulation results, figures, and supplementary tables of the manuscript *Impact of jail-based MOUD administration on post-release overdose mortality: an agent-based modeling study* from the contents of this repository. Installation of the model and its general use are described in [README.md](README.md).

## 1. Workflow overview

The results are produced in five stages (Table 1). Stage 2 requires a computing cluster: the scenario experiments consist of 17 sweep experiments with 156,600 simulation runs in total. The output of Stages 1–3, the combined sweep results, is included in the repository as `analysis/all_runs_response_combined.zip`. Stage 4 produces all manuscript figures from this file in less than one minute on a desktop computer. Stage 5 reproduces the time-on-treatment analysis of Appendix Section C.

**Table 1.** Workflow stages.

| Stage | Scripts | Input | Output | Resources |
|---|---|---|---|---|
| 1. Experiment definitions | `analysis/jccm_generate_sweep_upf.R` | Factor levels set in the script | 17 UPF files (included, `swift_proj/data/moud/`) | Seconds |
| 2. Simulation sweep and per-run responses | `swift_proj/swift/run_jccm_sweep.sh`, `swift_proj/swift/swift_run_sweep.swift`, `analysis/jccm_analyze_run_response.R` | Per experiment: one UPF file and the configuration file of its MOUD type; model input data | One `runs_response.csv` per run | About 29,000 core-hours |
| 3. Combination of per-run responses | `analysis/jccm_combin_run_responses.R` (once per experiment), R code in Section 5.2 | `runs_response.csv` files | One `runs_response_combined.csv` per experiment; `all_runs_response_combined.csv` (included as a zip archive) | Minutes |
| 4. Outcome, rate differences, and figures | `analysis/jccm_moud_analysis_linkage_to_care_plots.R` | `all_runs_response_combined.csv` | Figures 2–9 and the values reported in the Results | 40 s, 1 GB memory |
| 5. Time-on-treatment survival functions | `data/moud_km_survival.R` | `data/moud_time_on_treatment.csv` | Figures S1–S2, Table S5 | Seconds |

## 3. Stage 1: experiment definitions

### 3.1 Unrolled parameter files

Each line of an unrolled parameter file (UPF) is a JSON object that defines one simulation run. Its values override the configuration file. Example (first line of `upf_moud_meth_linkage_05.txt`):

```json
{"run":1,"naloxone.level.community":0,"cji.jail.initial.size":4000,"transition_OU*Overdose*Base_Probability":0.00043,"jail.oud.screen.probability":0.5,"moud.linkage.to.care.multiplier":0.5,"jail.moud.acceptance.rate":0.2,"jail.moud.type":"Methadone","experiment":1,"random.seed":1,"jail.loi.fractions":[0.25,0.25,0.5]}
```

**Table 3.** UPF fields.

| Field | Values in the paper experiments |
|---|---|
| `jail.moud.type` | One value per file: `Methadone`, `Buprenorphine_Sublingual`, `Buprenorphine_XR`, `Naltrexone_XR`, or `None` |
| `moud.linkage.to.care.multiplier` | One value per file: 0, 0.5, 1, 2 (1 in the no-MOUD file) |
| `cji.jail.initial.size` | 4,000; 6,000; 11,000 |
| `transition_OU*Overdose*Base_Probability` | 0.00043, 0.00066, 0.00086 (daily overdose probability; sets the NIHU and PWID values, which the results table records as `transition_NIHU*Overdose*Base_Probability` and `transition_PWID*Overdose*Base_Probability`) |
| `naloxone.level.community` | 0, 0.5, 1 |
| `jail.oud.screen.probability` | 0.5, 0.7, 0.9 (0 in the no-MOUD file) |
| `jail.moud.acceptance.rate` | 0.2, 0.5, 0.8 (0 in the no-MOUD file) |
| `jail.loi.fractions` | [0.25, 0.25, 0.5], equal to the configuration files |
| `random.seed` | 1–40 |
| `experiment` | Scenario index within the file: 1–243 (1–27 in the no-MOUD file) |
| `run` | Line number within the file |

`experiment` and `run` are not model parameters. They pass through the model output into the results table. Scenario indices restart in each file, so a scenario is identified by its parameter values together with `jail.moud.type` and `moud.linkage.to.care.multiplier`.

The 17 files in `swift_proj/data/moud/` are named `upf_moud_<MOUD>_linkage_<m>.txt`, where `<MOUD>` is `meth` (methadone), `bupsl` (SL buprenorphine), `bupxr` (XR buprenorphine), or `ntxxr` (XR naltrexone), and `<m>` is `0`, `05`, `1`, or `2` for multipliers 0, 0.5, 1, and 2. Each MOUD file holds 243 scenarios × 40 seeds = 9,720 runs. `upf_moud_none.txt` holds 27 scenarios × 40 seeds = 1,080 runs. The total is 3,915 scenarios and 156,600 runs.

### 3.2 Regeneration of the UPF files

`analysis/jccm_generate_sweep_upf.R` writes one UPF, `upf_json.txt`, to the working directory for the MOUD type and linkage multiplier set in the script. For the paper files, `jail.moud.type` and `moud.linkage.to.care.multiplier` must each hold a single value; the script sets screening and acceptance to 0 when the MOUD type is `None`. The following R code, run from the repository root, generates all 17 files in a temporary directory and compares them with the included files.

```r
gen   <- readLines("analysis/jccm_generate_sweep_upf.R")
i_mul <- grep("^moud.linkage.to.care.multiplier <-", gen)
i_typ <- grep("^jail.moud.type <-", gen)
types <- c(meth = "Methadone", bupsl = "Buprenorphine_Sublingual",
           bupxr = "Buprenorphine_XR", ntxxr = "Naltrexone_XR")
mults <- c("0" = 0, "05" = 0.5, "1" = 1, "2" = 2)
cases <- c(unlist(lapply(names(types), function(t) lapply(names(mults), function(m)
             list(file = sprintf("upf_moud_%s_linkage_%s.txt", t, m), type = types[[t]], mult = mults[[m]]))),
             recursive = FALSE),
           list(list(file = "upf_moud_none.txt", type = "None", mult = 1)))
repo <- getwd(); out <- tempfile("upf"); dir.create(out)
for (cs in cases) {
  g <- gen
  g[i_mul] <- sprintf("moud.linkage.to.care.multiplier <- %s", cs$mult)
  g[i_typ] <- sprintf("jail.moud.type <- '%s'", cs$type)
  setwd(out); eval(parse(text = g), envir = new.env()); setwd(repo)
  file.rename(file.path(out, "upf_json.txt"), file.path(out, cs$file))
  same <- unname(tools::md5sum(file.path(out, cs$file)) ==
                 tools::md5sum(file.path("swift_proj/data/moud", cs$file)))
  cat(sprintf("%-30s %s\n", cs$file, if (same) "identical" else "DIFFERENT"))
}
```

All 17 regenerated files are byte-for-byte identical to the included files.

### 4.2 Procedure within an experiment

`swift_proj/swift/swift_run_sweep.swift` runs each line of the UPF file of the experiment as one simulation run. For line *i* (counted from 0), it

1. creates `swift_proj/experiments/<EXPID>/runs/run_<i>/`;
2. inserts `"output.directory"` with this path into the JSON line;
3. runs the model through the Python interface of Swift/T with the configuration file of the experiment and the JSON line, on one process;
4. calls `tabulate_run()` from `analysis/jccm_analyze_run_response.R` with a warm-up period of 90 days, which writes `runs_response.csv`: one row with all parameter values of the run and 55 response variables. A failed run writes `run_failed.txt`.

The response script reads CSV model output, which is the default (`output.file.format: csv`). Each run reads the configuration file when it starts, so the configuration files must not be modified while a job is queued or running.

### 4.3 Launch script

`swift_proj/swift/run_jccm_sweep.sh` takes two arguments, the experiment ID and the configuration file (relative to `data/`). The UPF file is set in the script. Table 5 lists the settings to review before each launch.

**Table 5.** Settings in `run_jccm_sweep.sh`.

| Setting | Value in the paper sweep | Change |
|---|---|---|
| `-f=` argument of `swift-t` | `$EMEWS_PROJECT_ROOT/data/moud/<UPF file of the experiment>` | Set to the UPF file of each experiment (Table 4) before its launch |
| `PROCS`, `PPN` | 180, 18 (10 nodes) | Adapt to the cluster |
| `QUEUE`, `PROJECT` | Bebop queue and allocation; varied between experiments | Adapt to the cluster |
| `WALLTIME` | 12:00:00; 5:00:00 for `moud_none` | Adapt to the cluster |
| `MACHINE` | `pbs` | Scheduler name; empty string for execution on the local machine |
| `TURBINE_LAUNCHER` | Not set | `srun` on Slurm clusters if required |
| `PSM2_KASSIST_MODE` | `none` | Bebop-specific; remove elsewhere |
| `PYTHONPATH` | Repository root (set by the script) | None |

Requirements on the compute nodes: Swift/T built with Python and R support, the Python packages of the model (README, Requirements), and the R package `data.table`. When the R library of the user is not visible to the Swift/T processes, set `R_LIBS_USER` in the script. The script asks for confirmation when the experiment directory already exists, so it must be started interactively or with an empty experiment directory.

### 4.4 Launch

For each row of Table 4, set the `-f=` argument and launch the experiment with its ID and configuration file. For the methadone experiment with linkage multiplier 1:

```bash

./run_jccm_sweep.sh 2026_moud_meth_linkage_1 model_props_methadone.yaml
```

and for the no-MOUD experiment:

```bash
# in run_jccm_sweep.sh: -f="$EMEWS_PROJECT_ROOT/data/moud/upf_moud_none.txt"
./run_jccm_sweep.sh moud_none model_props_none.yaml
```

### 4.7 Subsets sufficient for the manuscript figures

The manuscript figures use a subset of the design. Figures 2–5 use jail population 6,000 and community naloxone 0.5: 17,280 MOUD runs and 120 no-MOUD runs (the no-MOUD runs give the dashed reference lines). Figures 6–9 also fix the baseline overdose probability at 0.00066: 5,760 MOUD runs. At about 3 min per run, the subset for Figures 2–9 requires about 870 core-hours. The subset can be extracted from the UPF files by field value:

```bash
cd swift_proj/data/moud
for f in upf_moud_*.txt; do
  grep '"cji.jail.initial.size":6000,' "$f" | grep '"naloxone.level.community":0.5,' > "subset_$f"
done
```

The Stage 4 script selects the figure scenarios by parameter value and runs unchanged on a subset. Results tables based on all scenarios (`summary_diff`, Section 6.4) then cover the subset only.

### 4.8 Single runs without Swift/T

The following shell code reproduces the procedure of Section 4.2 for one UPF line. Run it from the repository root, with the Python environment of the model active, and set `CFG` to the configuration file of the experiment (Table 4). Lines can be distributed over processes with `xargs -P` or GNU `parallel`.

```bash
export PYTHONPATH=$(pwd)
REPO=$(pwd)
UPF=swift_proj/data/moud/upf_moud_meth_linkage_1.txt
CFG=data/model_props_methadone.yaml
N=1                                                # line number in the UPF (1-based)
OUT=$REPO/local_proj/2026_moud_meth_linkage_1/runs/run_$((N-1))
mkdir -p "$OUT"
LINE=$(sed -n "${N}p" "$UPF")
JSON="{\"output.directory\": \"$OUT\", ${LINE:1}"   # insert output.directory after the opening brace
(cd "$OUT" && python3 -m jccm_model "$REPO/$CFG" "$JSON")
Rscript -e "source('$REPO/analysis/jccm_analyze_run_response.R');
            data.table::fwrite(tabulate_run('$OUT', use_parquet = FALSE, warm_up = 90),
                               '$OUT/runs_response.csv')"
```

## 5. Stage 3: combination of per-run responses

### 5.1 Combination within each experiment

`analysis/jccm_combin_run_responses.R` is run once for each of the 17 experiments. It reads the `runs_response.csv` files in `<experiment_dir>/runs/run_<i>/` and writes one table, `<experiment_dir>/runs_response_combined.csv`, with 9,720 rows for each MOUD experiment and 1,080 rows for the no-MOUD experiment. Before each execution:

- Set `experiment_dir` to the experiment directory, e.g. `swift_proj/experiments/2026_moud_meth_linkage_1`.
- The script joins paths with the Windows separator (`"\\runs"`, `"\\runs_response_combined.csv"`). On Linux and macOS, replace these with `"/runs"` and `"/runs_response_combined.csv"`.

The script also renames columns 16–18 to `loi.low`, `loi.med`, and `loi.hig`, because `fread` reads the YAML list `jail.loi.fractions` of `model_props.yaml` as three rows. It then rebuilds `jail.loi.fractions` as a text column at the end of the table. The column positions are valid for runs whose `model_props.yaml` contains the key `experiment`, which holds for all paper UPF lines.

### 5.2 Combination of all experiments

The 17 per-experiment `runs_response_combined.csv` files are stacked into one table, `all_runs_response_combined.csv`, which is included in the repository as `analysis/all_runs_response_combined.zip`. With the experiment directories below `swift_proj/experiments/`:

```r
library(data.table)
base_dir <- "swift_proj/experiments"
files <- list.files(base_dir, pattern = "^runs_response_combined\\.csv$",
                    recursive = TRUE, full.names = TRUE)
dt <- rbindlist(lapply(files, fread, fill = TRUE), fill = TRUE)
fwrite(dt, file.path(base_dir, "all_runs_response_combined.csv"))
```

The anchored pattern excludes `all_runs_response_combined.csv` from the input when the code is repeated. Rows follow the alphabetical order of the experiment directories; the analysis does not depend on row order. Stacking the 17 per-experiment tables of the paper sweep with this code gives a table equal in every value to the included file (156,600 rows, 108 columns, same column order).

### 5.3 Contents of `all_runs_response_combined.csv`

The table has one row per run. Of its 108 columns, 53 hold parameter values and run bookkeeping (`run`, `experiment`, `loi.low`, `loi.med`, `loi.hig`, `jail.loi.fractions`), and 55 hold response variables.

**Table 7.** Columns used in the manuscript analysis.

| Column | Content |
|---|---|
| `jail.moud.type`, `moud.linkage.to.care.multiplier`, `cji.jail.initial.size`, `transition_NIHU*Overdose*Base_Probability`, `naloxone.level.community`, `jail.oud.screen.probability`, `jail.moud.acceptance.rate`, `random.seed` | Scenario factors and replicate seed |
| `cji.all.size`, `cji.fraction.nihu`, `cji.fraction.pwid`, `stop.at`, `burnin.period.days` | Used to compute person-years |
| `released_persons_deaths` | Overdose deaths after day 90 of any agent ID that appears in a `jail_release` event after day 90. Agent IDs are reused when a deceased agent is replaced, so an ID can refer to successive agents. |

Other response columns count overdoses, deaths, deaths averted, naloxone kits, EMS calls, and jail releases by state, overall and for released persons, by gender, race and ethnicity, and age group. `mean_moud_time_on_treatment` is the mean of the `stop_moud` event values. These count days from MOUD initiation in jail, include time in jail, and exclude episodes ended by death or by the end of the run. The column is not a measure of post-release time on treatment and is not used in the manuscript. `data.dir` and `output.directory` hold paths on the cluster file system.

## 6. Stage 4: outcome, rate differences, and figures

### 6.1 Execution

`analysis/jccm_moud_analysis_linkage_to_care_plots.R` sets its input and output directories on lines 19–20 as absolute paths. Set them to the analysis directory; both values must end with `/`:

```r
base_dir   <- "./"
output_dir <- "plots_reproduced/"
```

Then run from `analysis/`:

```bash
cd analysis
unzip all_runs_response_combined.zip        # 122 MB CSV
mkdir -p plots_reproduced
Rscript jccm_moud_analysis_linkage_to_care_plots.R
```

The script requires the R packages `data.table`, `tidyverse`, `ggplot2`, `ggridges`, `scales`, `viridis`, `ggh4x`, `patchwork`, and `forestploter`. `ggh4x` and `patchwork` are used by exploratory plots that precede the manuscript figures in the script, so both must be installed for the script to complete.

### 6.2 Computation

1. **Person-years.** The population at risk is `cji.all.size` × (`cji.fraction.nihu` + `cji.fraction.pwid`) = 50,000 × 0.135 = 6,750 persons. The analysis period is (`stop.at` − `burnin.period.days`) / 365 = (1,915 − 90) / 365 = 5 years, which gives 33,750 person-years.
2. **Outcome.** For each run, the post-release OOD mortality rate per 1,000 person-years is `released_persons_deaths` / 33.75.
3. **No-MOUD reference.** For each combination of jail population, community naloxone, and baseline overdose probability, the mean rate over the 40 no-MOUD runs gives the dashed reference lines of Figures 2–5.
4. **Rate differences.** For each MOUD run, the rate difference is its rate minus the rate of the run with the same parameter values, linkage multiplier 1, and the same random seed.
5. **Summaries.** For each scenario, the median and interquartile range (IQR) of the rate and of the rate difference are computed over the 40 seeds. Means with *t*-based 95% confidence intervals are also computed but are not shown in the figures.
6. **Excess or averted deaths over 5 years.** The 1-year value is rounded to an integer, round(median difference / 1,000 × 6,750), and then multiplied by 5. The quartiles are treated in the same way. The 5-year values are therefore multiples of 5.
7. **Figure scenarios.** Jail population 6,000 and community naloxone 0.5. Figures 6–9 also fix the baseline overdose probability at 0.00066 (`od_base_prob` = 0.066, in percent).

### 6.4 Tabular results

The data frame `summary_diff` holds the summaries of Section 6.2 for all 3,915 scenarios. It can be written to a file or queried at the end of the script, for example for the reference scenario of the Results:

